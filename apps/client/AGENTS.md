# Client App DOX

## Purpose

- Vite + React app. Manage landing-page projects, prompt landing-page agent, preview each generated single-file HTML.
- `/` lists saved projects; `/projects/new` creates draft, redirects to `/projects/:id`; `/projects/:id` = editor: sandboxed `srcDoc` iframe preview + draggable prompt/conversation panel.

## Ownership

- `src/main.tsx`: `BrowserRouter` + route table (`/`, `/projects/new`, `/projects/:id`), `ThemeProvider` root, `TooltipProvider` root (all tooltips descend from it).
- `src/App.tsx`: `EditorPage` (preview + prompt panel composition), param-driven, keyed by project id. In dev, exported component identity + latest render fn bridged through `import.meta.hot.data`; inline `accept` callback rerenders stable component so App HMR reconciles around existing preview iframe instead of remounting.
- `src/components/projects-page.tsx`: website studio library with a desktop navigation rail and a default preview gallery; the Gallery/List control offers compact aligned rows with the same native editor links and action menus. Phone layout replaces the rail filters with a dropdown and keeps search, sorting, view choice, theme, and New project reachable. Titles wrap to two lines with original-brief excerpts; run status and edited dates remain visible. Search covers titles and briefs, has a visible label and one live result count; filter counts derive from project statuses. Query, filter, sort, view, and scroll persist per browser session. Rename uses a titled dialog with focus return; deletion has a named irreversible confirmation and pending/error feedback. Load errors offer retry. Shared `project-preview.tsx` fetches full HTML only near the viewport, keeps thumbnails inert and sandboxed without scripts, and scales a fixed 1440 × 900 viewport using ResizeObserver to fit gallery, list, and switcher sizes. Also owns the theme toggle and new-project redirect: creation shares one promise through Strict Mode, carries a stable UUID `creationKey`, and retries with the same key.
- `src/components/`: app-specific UI (error banner, theme provider, `editor-page-actions.tsx` menu actions injected into the chat panel). Theme context identity survives HMR through `import.meta.hot.data`, matching the stable editor boundary. `LandingPreview` React component consumed from dedicated `@workspace/landing-preview/react` Fast Refresh boundary (see `packages/landing-preview/AGENTS.md`); preview utilities remain in package barrel. Prompt panel consumed from `@workspace/prompt-panel`; `project-switcher.tsx` provides an in-panel searchable project list with recent/name sorting, current-project indication, and native links to New project and the full library. `EditorPage` injects `projectSwitcher`, `onAllProjects`, `theme`, `onToggleTheme`, `onLayoutChange`, sizes preview iframe from reported panel layout (init via `readStoredPanelLayout`).
- `src/hooks/`: streaming hooks + `use-model-pricing.ts` (fetches `GET /api/models?ids=…` once per session, scoped to the picker's supported base ids derived from `LANDING_MODEL_GROUPS`; live per-1M pricing + `contextLength` passed to `PromptPanel` as `modelPricing`, panel falls back to bundled static map when unavailable). `use-landing-page.ts` also owns the autocompaction threshold preference (`compactionPercent`/`setCompactionPercent`, 1–100, default 80, persisted to localStorage `landing.compactionPercent.v1`), posted as `compactionPercent` on every `/agent` send.
- `src/lib/`: `project-session.ts` is the pure authoritative snapshot/live-event/pending-submission reducer and delegates turn updates to `@workspace/conversation`; `sse-client.ts` validates bounded SSE framing and `reconnecting-stream.ts` owns retry, heartbeat-idle, and cleanup. `project-drafts.ts` keeps per-project prompt and attachment drafts in IndexedDB, with a synchronous cache for navigation races. The mounted session holds the immutable effective command for an uncertain retry; rejected/unknown input stays in the draft store, and confirmed terminal runs clear represented drafts. `use-project-draft.ts` gates edits until hydration completes. Project REST helpers validate shared `@workspace/contracts` schemas. Browser screenshot capture + preview iframe/morph helpers live in `@workspace/landing-preview`.
- `components.json`: shadcn project config targeting shared UI code in `packages/ui`.

## Local Contracts

- The first-party editor uses protocol v2: `GET /api/projects/:id/events?v=2` starts with a validated authoritative `state` snapshot, then validated committed `project_event` frames keyed by durable sequence. Reconnect always requests a fresh snapshot; cursors detect duplicates/gaps rather than promising historical HTML replay. Heartbeats keep idle connections observable. Fatal schema/version/size failures remain unavailable with their specific reason; EOF, silence, and transient transport failures reconnect with bounded backoff while retaining the last valid state. The legacy unversioned SSE endpoint remains server-supported.
- `project-session.ts` owns connection state, explicit run identity, cursor, optimistic requests, acceptance evidence, terminal precedence, and metadata/document updates. The hook never infers event ownership from a local active-turn ref. A committed acceptance or terminal outranks a late HTTP error, and an older turn cannot unlock a newer remote run.
- Each send captures one immutable input, stable browser-created `turnId`, project/session generation, and draft revision. `onSend` resolves `{ turnId, outcome:'accepted'|'rejected'|'unknown', reason? }`; only confirmed acceptance clears that exact unchanged draft revision. Rejected or uncertain commands retain full prompt and attachment bytes. Network/storage-uncertain results reuse the same idempotent command after a fresh snapshot; deterministic validation/conflict results reject it. Sends are unavailable before initial hydration and stay locked while the first request is in flight.
- Server owns project HTML. The v2 snapshot seeds HTML/models/identity/turns/run state; `document_changed` carries a committed hash and live HTML only when the current bytes match. A missing live body or sequence gap triggers resnapshot. Timers, readers, and async results are fenced by project plus mounted-session lifetime and cleaned on switch/unmount.
- Projects read via `src/lib/projects-api.ts` against `/api/projects*`. Full project reads include persisted `messages`; `use-landing-page.ts` restores them into prompt panel as non-streaming turns on editor mount. Projects list stays metadata-first, but rows may fetch full projects to render sandboxed `srcDoc` iframe previews. Stored HTML uses root-relative project image URLs (`/api/projects/:id/images/<file>`); `expandProjectImageUrls` expands to absolute before rendering editor/list preview iframes.
- Editor preview inits sandboxed `srcDoc` iframe permitting forms, modals, popups, same-origin storage, scripts; applies routine `html_update` changes in-place with same-document DOM morph helper rather than replacing `srcDoc`. Script-changing updates rerun scripts inside existing iframe doc instead of refreshing frame. HMR must preserve live generated iframe document. Keep `EditorPage` on stable `import.meta.hot.data` proxy with inline `import.meta.hot.accept` rerender; keep preview component import on dedicated `@workspace/landing-preview/react` Fast Refresh boundary, not mixed utility barrel. Client dynamically injects `<base href="about:srcdoc">` into preview HTML before initial `srcDoc` loads + morph targets only, so generated `#section` links resolve inside iframe without changing persisted project HTML. Content + message history pulled from server (not generated/persisted in browser). Composer element-selection toggle installs iframe-local capture listeners, resolves hover/click targets with `elementsFromPoint`, blocks generated-page interactions while active, renders animated pointer-events-none dashed accent overlay box around hovered/selected elements, then attaches selected element as selector-only metadata payload `{ kind: 'element', selector }` to prompt. Server captures each selector at mobile/tablet/desktop via Cloudflare Browser Run; client never rasterizes DOM elements. Do not reintroduce full workspace snapshot, client-side message save path, or browser AI SDK tool loop without updating plans + DOX.
- Prompt panel composer action row ordered: element select, image attach, model selector, cumulative project spend. Model selector names the primary text model and opens its list first; Advanced models reveals keyboard-navigable Text/Image/Vision tabs, role explanations, and vision linkage. Selections remain bound to `LandingModels` selection (`{ text, vision, image }`); every Text selection uses OpenRouter's `:nitro` routing variant, including restored legacy selections; Image + Vision ids unchanged. Selections persist immediately via `PATCH /api/projects/:id { textModel, visionModel, imageModel }`; individual saved message turns still show text model used for that turn. Server persists all 3 selections (`textModel`, `visionModel`, `imageModel`) to project metadata via `PATCH`, survive reload; per-request `/agent` call still sends them so run uses current selection. Spend trigger opens popover with cumulative project cost/category + token totals, updates from rolling stats whenever provider cost/usage becomes known after LLM step or terminal tool event (incl. active turn), replaces old per-turn Spend / tokens blocks. Cost formatting owned by `@workspace/prompt-panel`: popup details display USD with exactly 4 digits after decimal point; icon-free popup trigger shows only dollar amount rounded to 2 digits.
- One unified panel keeps the same expanded/condensed header: display-only 20px blob, Projects, Refresh, Panel layout, Viewport, Minimize/restore; no visible title or detached toolbar. `src/components/editor-page-actions.tsx` exports `PreviewRefreshButton` and `EditorPageActions` (rename + HTML download). `App.tsx` injects refresh and shared `PreviewViewportMenu` through `pageHeaderActions`, rename/download through `pageActions` into Panel layout. Refresh/export disable for empty/starter HTML; refresh bumps the iframe reload token locally and announces completion, export fetches a blob with pending/error/retry feedback without navigating. Consumer-owned viewport choices remain desktop full/tablet 768px/mobile 390px and work while minimized. Only conversation/composer hide on minimize; header and content stay mounted, preserving drafts and floating height. Projects opens its in-panel switcher; accepted sends expand conversation. Panel layout nests Settings: theme, shared motion preference, and Advanced summarization controls (default 80%). Rename is also available in the project library.
- Desktop editor is an edge-to-edge page with a compact 352 × 360 floating assistant in the lower-right corner by default. Optional left/right docking reserves `--landing-panel-width`; floating or minimized chat reserves no column. Both docked sidebars fill the viewport from top to bottom, with all controls inside the same panel. Docking must never inherit the floating top gap. Mobile retains the full page beneath a bottom overlay. Tablet/mobile preview frames stay at their exact width and scroll within the stage if needed. CSS and motion live in `packages/ui` globals. Minimizing never remounts the conversation or preview; restore returns keyboard focus to the composer. The new widget geometry uses panel storage v2; old v1 positions stay untouched and are not applied.

- Prompt message markdown renders with Streamdown; code fences must use `@streamdown/code` syntax highlighting with Catppuccin Latte/Mocha configured on code plugin (Streamdown reads `plugins.code.getThemes()` before `shikiTheme` prop) + panel-scoped Streamdown styling so headings, tables, lists, inline code, code blocks match the square glass panel language. Keep highlighted code line wrappers block-level when line numbers off so multiline fences do not collapse into one visual line. Code-block outer chrome uses square corners; hide copy/download controls.
- Each turn keeps the request, real activity summary, result, and recovery actions in reading order. Thinking/tool steps are grouped under one optional activity disclosure; individual diagnostics remain collapsed until opened. Tool intent is clamped to two lines in the header and fully available inside, including validated image previews, arguments, timing, and errors.
- Use `@workspace/ui/...` + `@workspace/prompt-panel` for shared package imports; `#components`, `#hooks`, `#lib` for app-local aliases.
- Do not put secrets in client code; only `VITE_*` variables client-readable.
- Use the liquid-glass material system from `packages/ui`; keep generated iframe content crisp and independent of app chrome.

## Work Guidance

- Follow shadcn/Tailwind rules: semantic tokens, `cn()` for conditional classes, `gap-*` over `space-*`, `size-*` for square dimensions, existing UI components before custom markup.
- Keep streaming state changes in hooks; keep prompt UI components mostly presentational.
- Update client event model + server SSE mapping together. Failed tool calls + failed turns must render with destructive/red styling; any still-running tool rows must be terminalized when run errors, completes, or is stopped. Agent-run errors stay inside turn; reserve global error banner for app/preview/load failures.
