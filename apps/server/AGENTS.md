# Server App DOX

## Purpose

- Node HTTP API for landing-page agent.
- Runs agent decoupled from requests (fire-and-forget `POST /agent`); progress streamed via `GET /api/projects/:id/events` subscribe; serves gen images; owns project-HTML screenshot capture via publish + Firecrawl scrape.

## Ownership

- `src/runtime.ts` + `src/production-runtime.ts`: explicit runtime composition and production bootstrap; each runtime owns its application services, repository, image store, run bus, model caches, Mastra storage/observability, agent runner, and awaited disposal. Production computes the existing `.data` and cwd-relative DB destinations once and passes absolute paths.
- `src/application/`: durable run admission/terminal/recovery ownership and tombstone-driven project creation/deletion coordination.
- `src/http/`: protocol-v2 snapshot/tail and authoritative project-list SSE delivery with bounded subscriber queues, framing, heartbeats, and backpressure cleanup.
- `src/index.ts`: side-effect-free custom Node HTTP server factory, CORS; `/agent`, `/api/models`, `/api/projects*` REST (incl `/api/projects/:id/stop` graceful run stop), `/images/:id`, `/api/projects/:id/images/:file`, `/api/projects/:id/screenshots/:file` routing.
- `src/config*.ts`: env parsing + runtime config, incl optional Firecrawl key (scrape + screenshot browser sandbox).
- `src/http-body.ts`: request body read helper.
- `src/model-catalog.ts`: OpenRouter `/models` catalog proxy for the UI model picker — slim per-1M-token pricing map (input/output/cache-read) via the provider transport, in-process TTL cache (5 min, matches upstream `max-age`), stale-on-error fallback to last good snapshot, `filterModelPricing` scopes to caller-requested supported ids, `createModelCatalog()` owns the TTL/inflight/image-price caches and exposes a reset hook for its own tests.
- `src/providers/`: bounded provider transport plus run-owned operation scopes, cancellation, write leases, usage reports, and bounded draining.
- `src/mastra/`: Mastra agent, tools, model wiring, SSE mapping, cost accounting, publish+scrape screenshot capture, file-backed project storage.
- `.data/`: local-only persisted projects (gitignored) under `projects/<id>/` w/ atomically replaced `project.json`, `html.json`, and rebuildable `run-state.json`; sequenced `client-messages.jsonl` (durable acceptance/output/lifecycle records flush before publication; `html_update` excluded); immutable accepted uploads in `attachments/<sha256>.<ext>`; best-effort inspection logs `agent-messages.jsonl` and `vision-messages.json`; `screenshots/<NNN>-<uuid>.<ext>`; immutable generated `images/img-<uuid>.<ext>`. Minimal deletion markers live outside project directories under `project-tombstones/<id>.json`. Legacy numeric image names, `messages.json`/`raw-messages.json`, and import-only `index.html` remain readable. An incomplete client-journal tail blocks appends until an explicit `recoverClientJournal(projectId)` call quarantines its exact bytes and flushes the valid prefix; ordinary reads and boot recovery never mutate it.
- `.mastra/`: generated Mastra CLI build/studio output; do not hand-edit.

## Local Contracts

- `GET /api/models` returns `{ ok, models: Record<id, { input, output, cacheRead?, contextLength?, image?, imageOutput?, inputModalities? }> }` — per-1M-token USD prices (`image` = USD/output image, `imageOutput` = USD/1M image-output tokens for image models) + `contextLength` (upstream `context_length`) the model picker displays, proxied + slimmed from OpenRouter's public `/models` catalog (in-process 5-min TTL cache, concurrent callers share one refresh, refresh failure serves stale snapshot; `502` JSON when no snapshot exists so the client falls back to its bundled static pricing). Image-generation-only models absent from the chat catalog (Seedream, GPT Image, Grok Imagine) are enriched from OpenRouter's images API (`/images/models/:id/endpoints`, per-id TTL cache incl negative entries, failed ids skipped silently — never 502 the route). `?ids=a/b,c/d` scopes the response to the app's supported models (the first-party client sends its picker option ids from `LANDING_MODEL_GROUPS`, suffix-stripped; unknown ids ignored); without the param the full slim catalog is returned (no images-API enrichment).
- `POST /agent` accepts `{ prompt: string, projectId: string, turnId?: string, textModel?: string, imageModel?: string, visionModel?: string, compactionPercent?: number, attachments?: Attachment[] }`; `compactionPercent` (1–100) sets the Observational Memory observation threshold as a percent of the text model's catalog context window (omitted/unknown window → OM default). attachments = uploaded image data URLs or selector-only element records `{ kind: 'element', selector }`; payloads validated server-side. Uploaded bytes become immutable project assets, and the committed acceptance record contains only their digest/size/media/name/path manifest. Supplied `turnId` = non-empty strings ≤128 chars and an idempotency key within the project (omission → generated fallback): an identical retry joins/reuses its acceptance, changed canonical content conflicts, and a legacy turn without a verifiable digest requires a new ID. Process-local server accepts one active run per project; acceptance commits before acknowledgment or provider work, and a different turn overlaps with `409`. Three model fields select OpenRouter model per role (text brain, image gen, vision OCR — used only when text model lacks image input), default `config.openrouter.default{Chat,Image,Vision}Model`; default chat model uses OpenRouter `:nitro` routing variant. Returns JSON `{ ok, status:'running', turnId }` after durable acceptance; run remains decoupled from the request. Run events commit before publication; ordered output precedes one canonical `run_terminal`, then legacy terminal SSE projection. `run_blocked` records known usage without fabricating completion and retains the project gate until local settlement or restart recovery. Full HTML remains outside the journal; content commits add a lightweight `document_changed` hash/byte record. Agent edits the anchored `html.json`; `GET /api/projects/:id` remains canonical full project read path.
- JSON bodies bounded while streaming: `/agent` ≤24 MiB encoded, project create/PATCH ≤64 KiB; overflow → JSON `413` before route side effects. Attachment limits use decoded bytes for uploaded images (8 MiB each, 16 MiB aggregate); selector-only element attachments = 0 bytes. Declared uploaded attachment `size` must exactly match decoded data URL.
- Server defaults to loopback `HOST=127.0.0.1` + one exact `CLIENT_ORIGIN=http://localhost:5173`. Present browser origins must match configured HTTP(S) origin exactly; mismatches (incl `null` + OPTIONS) → JSON `403` before route side effects. Origin-less CLI/server requests allowed. Allowed responses advertise only configured origin w/ `Vary: Origin`. Non-loopback bind = unauthenticated, requires operator-controlled network boundary.
- Project REST API (file-backed via `src/mastra/lib/project-store.ts` under `.data/projects/<id>/`):
  - `GET /api/projects` → list metadata; drafts (no HTML) hidden.
  - `POST /api/projects { title?, textModel?, creationKey? }` → create draft (seeded with placeholder page). A validated UUID creationKey identifies one logical operation; concurrent calls share the repository promise and retries after restart return the existing draft. Invalid keys are rejected before writes.
  - `GET /api/projects/:id` → full project (metadata + `indexHtml` + persisted `messages`).
  - `PATCH /api/projects/:id { title?, textModel?, visionModel?, imageModel? }` → rename and/or persist model selection; title or textModel required, all provided strings nonempty, title at most 120 characters; `project.json` RMW synchronous, so can't lose concurrent edit's `hasHtml` write.
  - Project identity stores the original first-prompt `brief` separately from `title` and `titleSource` (brief/page/user). Generated HTML titles name automatic projects and publish `project_meta` only after the atomic metadata write commits; user renames are protected from later edits. Legacy rows migrate once on read only when their title matches their first brief or Untitled; other names remain user-owned. Subsequent library reads remain metadata-only.
  - `DELETE /api/projects/:id` → acquire the application deletion gate, commit a tombstone, stop/drain the owner, revoke writes, verify Observational Memory/thread cleanup, then remove project files. Unsettled or unhealthy lifecycle work returns `409`; retries resume incomplete deletion, completed deletion is idempotent, and the creation key cannot recreate the removed project.
  - `POST /api/projects/:id/stop` → gracefully stop active run for project: aborts attachment analysis, Firecrawl capture, or Mastra stream; after provider work drains, terminal `stats` + stopped state + `done` broadcast to subscribers. Work that exceeds the drain grace emits incomplete accounting and keeps the project fenced (returns `{ ok, stopped }`, `stopped=false` when no run active).
  - `GET /api/projects/:id/events?v=2` → one validated coherent `state` snapshot plus committed sequenced `project_event` tail. The subscriber queue is installed before snapshot I/O; document events enrich with HTML only when the current hash matches. Bounded queues/backpressure close slow clients for fresh-snapshot reconnect. Unversioned requests retain legacy snapshot/run-bus delivery.
  - `GET /api/projects/events?v=2` → authoritative full `list_state` frames, including an empty list. It subscribes before the first read, coalesces invalidations for at most 50 ms, serializes refreshes, and retains dirtiness during an active refresh. Unversioned requests retain individual `project_status` events.
  - `GET /api/projects/:id/images/:file` → serve persisted project image.
  - `GET /api/projects/:id/screenshots/:file` → serve persisted screenshot under `screenshots/`.
- `GET /images/:id` serves a live generated-image buffer or its runtime mapping to already-persisted project bytes. Project-bound generation publishes the stable `/api/projects/:id/images/:file` URL only after exclusive file creation and file/directory flush; projectless Studio generation keeps the temporary route.
- Optional env: `OPENROUTER_API_KEY` (required for any model calls), `OPENROUTER_API_URL`, `OPENROUTER_CHAT_MODEL`, `OPENROUTER_IMAGE_MODEL`, `OPENROUTER_VISION_MODEL`, `CLIENT_ORIGIN`, `HOST`, `PORT`, `FIRECRAWL_API_KEY` (scrape + screenshot capture), `FIRECRAWL_API_URL`, `FIRECRAWL_CREDIT_USD` (default `0.002`), `PROVIDER_OPERATION_TIMEOUT_MS` (default `120000` for each non-streaming operation including attempts/backoff/body), `PROVIDER_DRAIN_GRACE_MS` (default `5000`), `PROVIDER_METADATA_TIMEOUT_MS` (default `10000` for final Mastra usage/finish reason), `MASTRA_PLATFORM_ACCESS_TOKEN`, `MASTRA_PROJECT_ID`, `SERVER_BASE_URL` (server's own origin used to build absolute image/screenshot URLs the agent embeds in HTML; defaults to `http://${HOST}:${PORT}` — Host header is ignored, so set explicitly when behind a proxy), `AGENT_MODEL_MAX_RETRIES`, `AGENT_STREAM_ERROR_MAX_RETRIES`, `AGENT_RETRY_BASE_DELAY_MS`, `AGENT_RETRY_MAX_DELAY_MS`, `AGENT_MAX_COST_USD` (per-run USD cap, default `5`; set `0` to disable, checked after every known provider charge including Firecrawl and bundled scrape OCR), `AGENT_CONTEXT_TOKEN_LIMIT`, `AGENT_TEMPERATURE`, and `AGENT_TOP_P`.
- Run lifetime: `POST /agent` is fire-and-forget — closing the tab is delivery loss, and a reopened tab can resubscribe. The application coordinator owns acceptance, execution, bounded draining, one canonical terminal commit, projection, and release. `run-state.json` is rebuilt from journal lifecycle records. On boot, accepted nonterminal work becomes interrupted exactly once and terminal records repair stale projections; provider work is never automatically repeated. Journals with an incomplete tail remain blocked until explicit repair.
- Keep secrets out of logs + source; `.env` stays app-local + ignored; `apps/server/.env.example` = tracked non-secret sample to copy.
- Keep `createApiServer(runtime)` free of listening, recovery, storage construction, and provider side effects. Direct execution dynamically loads the production bootstrap, resumes tombstoned deletions, repairs lifecycle projections only in its explicit repository root, then listens.
- File snapshots expose rendered HTML + hash, metadata, validated client records, legacy message fallback, and a committed journal watermark from one stable repository revision. Callers retry the typed busy result; incomplete-tail and durability-uncertain states remain explicit.
- Mastra local stores (`mastra.db*`, `mastra.duckdb*`) = generated runtime artifacts; must stay out of source edits. `mastra.db` additionally holds Observational Memory threads (agent conversation history, keyed by projectId) — deleting it loses agent context for existing projects (client/UI logs under `.data/` remain the durable record).
